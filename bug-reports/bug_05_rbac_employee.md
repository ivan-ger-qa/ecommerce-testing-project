# BUG-005 — Нарушение ролевой модели при создании корпорации для пользователя с ролью `employee` или `passenger`

**Модуль:** Управление корпорациями (API)
**Severity:** High
**Priority:** High
**Status:** Open

---

## Окружение

**Server:** `api.brainy.run/go`
**Endpoint:** `POST /create_corporation`

---

## Предусловия

* Пользователь авторизован с использованием **Basic Auth**.
* Используются валидные учетные данные Школы Брейни.
* Существует пользователь с `ID 247`, имеющий роль `employee` или `passenger`.

---

## Шаги воспроизведения

### 1. Отправить POST-запрос

```http
POST https://api.brainy.run/go/create_corporation
```

### 2. Передать в `owner_id` ID пользователя с ролью `employee` или `passenger`

```json
{
  "logo_url": "https://s3.ru1.storage.beget.cloud/bb4e0f3f0f81-brainy-platform/API%2FGO%2Frobbie.jpg",
  "name": "ivan-defis",
  "owner_id": 247
}
```

### 3. Отправить запрос

Проверить HTTP-статус и тело ответа.

---

## Ожидаемый результат

Система должна проверить роль пользователя, указанного в `owner_id`.

Поскольку пользователь `ID 247` имеет роль `employee` или `passenger`, создание корпорации должно быть запрещено.

Сервер должен вернуть HTTP-код `400 Bad Request`.

Ожидаемое тело ответа:

```json
{
  "message": "Ошибка валидации. Проверьте введенные данные."
}
```

Корпорация не должна быть создана.

---

## Фактический результат

Проверка роли пользователя отсутствует.

Система успешно создаёт корпорацию для пользователя с ролью `employee` или `passenger`.

Сервер возвращает HTTP-код `201 Created`.

Фактическое тело ответа:

```json
{
  "corporation_id": 5266,
  "message": "Корпорация успешно создана"
}
```

---

## Результат

API не проверяет соответствие роли пользователя требованиям для создания корпорации.

Пользователь с ролью `employee` или `passenger` может быть указан в качестве владельца корпорации, несмотря на отсутствие соответствующих прав.

Это позволяет обойти предусмотренную ролевую модель системы.

**Status:** Open
